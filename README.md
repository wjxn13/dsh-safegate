# dsh-safegate

**给 AI 编码代理的工具调用加一道风险门：低危直接放行，中危/高危弹窗问一次。**

面向 [DeepSeek Harness（DSH）](https://www.deepseek.com/) 的 `PreToolUse` hook，覆盖
`bash` / `pwsh` / `edit` / `write` / `str_replace_editor` / `cordis_run`。

```
AI 要执行 rm -rf something
   → PreToolUse hook 触发
   → 本插件从 stdin 读一行 JSON，调规则引擎判风险档
   → 往 stdout 写一行 JSON（allow / ask）
   → DSH 照此决定：直接执行 / 弹窗问你
```

**当前形态：纯规则，不接模型。** 这不是偷懒，是测过之后的结论 —— 见下。

## 为什么是纯规则

我原本的打算是「规则打底 + 小模型复核」。为此做了两组实验，两组都指向同一个结论：
**模型不该进这条链路**。实验脚本与原始数据不在此仓库（含真实用户消息，不公开），
这里只记结论与判据。

### 实验一：授权语境实验（240 次调用）

设计：12 条固定提案 × 5 种用户语境（明确授权 / 含糊 / 沉默 / 无 / 明确拒绝）×
2 种问句措辞 × 2 次重复。工具调用字节在所有语境下完全一致，只有用户消息变。

| 问句臂 | AUC | 最优阈值 | 最优准确率 | 分离度 | ECE |
|---|---|---|---|---|---|
| 我们的措辞 | **0.462** | 0.974 | 58.3% | −0.024 | 0.482 |
| 上游模板措辞 | **0.972** | 0.940 | 95.8% | +0.134 | 0.409 |

关键点：

- 两个臂在默认阈值下的**准确率都是 50%**，但那是**两种相反的病**。
  前者 AUC 0.462（比抛硬币还差）⇒ 输入它压根不看，换阈值救不回来；
  后者 AUC 0.972 ⇒ 分得开，只是标定偏了。
  **只报准确率会把这两件事混成一句话。**
- 后者 8/48 次翻转**全是 allow → block**（只增多问，从不减少）。
  对一个「非对称门控」（模型只能升档、不能降档）来说，这恰恰是没用的那一半。
- **阈值逃逸**：把阈值调到能放过所有"明确授权"项的位置，
  所有 10 个「问句臂 × 语境」组合**都至少漏掉 9 条必问项中的 5 条**。
  最刺眼的一条：模型把「删用户桌面目录」判得**比「删会话草稿」更安全**。
- 同一批 12 条交给规则层：**11/12 判对，漏放 0**。

### 实验二：反向实验（找规则的漏网之鱼）

换个方向：让模型去扫规则层判 `low` 的 2877 条真实调用，看能不能捞出真漏放。

- 能捞。人工审 top-40，捞出 4 条真漏放，其中 3 条变成了补丁 E / F / G。
- 但**不能让它在线上做这件事**：阈值 0.5 下它会多问 **+244 条（+8.5%）**，
  其中约 35% 是 `cd xxx && ...` 这类复合命令（多为误报），15.6% 是刻意判温和的杀进程。
  为一个 4 条的真收益，付 244 条打扰 —— 不划算。

⇒ 结论：**模型离线跑、人看 top-N、把结论固化成规则**。线上只跑规则。

## 文件结构

```
dsh-safegate/
├── real_policy.py              规则引擎（唯一的规则定义处）
├── install.py                  生成本机 hook 配置
├── dsh_hook/
│   ├── gate_hook.py            适配层：翻译 DSH 的输入/输出，规则一行不重写
│   ├── hooks.json.template     配置模板（占位符，不含本机路径）
│   ├── cordis_insert_block.yml 要贴进 DSH 配置的 insert 块
│   ├── preflight.py            装之前的自检
│   └── check_coverage.py       检查：还有哪些工具**没被**门控覆盖
└── tests/
    └── test_hardening_rules.py 80 条边界用例（正例/负例成对）
```

**规则只有一处定义。** `gate_hook.py` 不重写任何规则，只做三件事：
翻译输入、翻译输出、映射工具名。两边各写一份必然漂移，而漂移不抛异常、只让数字说谎。

## 安装

```bash
git clone https://github.com/wjxn13/dsh-safegate.git
cd dsh-safegate
python install.py           # 生成 dsh_hook/hooks.json + 跑自测
python install.py --apply   # 再把 insert 块追加进 $DSH_HOME/cordis.patch.yml（会先备份）
```

`install.py` 做的事：把模板里的 `__PYTHON__` / `__REPO__` 替换成本机真实路径。

> **为什么必须有个安装步骤**：hook 配置里写绝对路径，DSH 不会帮你展开 `~`。
> 而仓库里如果写死 `C:/Users/<某人>/...`，一公开就把用户名发布出去了。
> ⇒ 模板进仓库，真实路径本机生成，生成的 `hooks.json` 在 `.gitignore` 里。

改完配置**必须重启 dsh** 才生效（profile 没开 `patchReload=live` 时不会热重载）。

卸载：删掉 `cordis.patch.yml` 里那个 `id: dsh-gate-hook` 的 insert 块，重启。

## 判定是怎么做的

### 三档 → 三种处置

| 风险档 | 分数 | 处置 |
|---|---|---|
| `low` | < 0.35 | `allow`，直接放行，用户无感 |
| `medium` | 0.35 – 0.75 | `ask`，弹窗问 |
| `high` | ≥ 0.75 | `ask`，弹窗问（**不自动拒绝**） |
| 不认识的工具 | — | `ask`（**fail-closed**：我们不知道 = 该问） |

> 为什么 `high` 也走 `ask` 而不是 `deny`：实测教训是「**被拦下 ≠ 用户会拒绝**」。
> 门控的职责是给用户一个拦截的机会，不是替用户做决定。硬 `deny` 会让用户
> 连「这次我确实要删」都表达不了。

### 三张模式表

`_HIGH_PATTERNS` / `_MEDIUM_PATTERNS` / `_MILD_PATTERNS`，逐条正则打分，
再由 `_scope_adjust()` 按**目标**上调或下调。

### 三条不那么显然的规则

**① 危险在载荷，不在动词。**
`Start-Process powershell -ArgumentList "Remove-Item -Recurse -Force D:/data"` ——
动词是无害的「启动进程」，危险来自 `-ArgumentList` 里的载荷。
所以 `-ArgumentList` 的载荷会**照扫一遍**（见 `_EXECUTES_CODE`）。

**② 可再生 ≠ 无风险，但确实降一档。**
`node_modules/`、`__pycache__/`、`.bak`、`/tmp/`、`_probe_` 这类路径删了必然能再生，
命中后**只降到 0.50（medium，仍然要问）**，绝不降成 `low` 直接放行 —— 放宽不带漏报风险。

**③ heredoc 要区分数据与代码。**
`cat > f <<'EOF'` / `tee` 是**写数据**（剥掉）；
`python - <<'PY'` / `node -e` 是**代码**（必须扫）。

### 一个刻意的设计：不写死用户名

`TRUSTED_ROOTS`、`_HOME`、Temp 路径全部从 `~` 推导，可用环境变量覆盖：

```bash
export SAFEGATE_TRUSTED_ROOTS="D:/work;E:/data"   # 分号分隔
export DSH_HOME="$HOME/.dsh"
```

每一条都来自真实调用回放里的具体漏放或误报，不是拍脑袋加的。

| 补丁 | 日期 | 改了什么 | 为什么 |
|---|---|---|---|
| **A / B** | 09-28 | `Set-Content`/`Out-File`、`schtasks` 改为**按目标路径**判 | 同样是写文件，写 `c:\windows` 和写项目目录不是一个量级 |
| **D1** | 09-28 | 本命令**自己造出来**的文件，删掉判可再生 | 唯一一条靠构造成立、不需要猜的判据 |
| **D2** | 09-28 | `_probe/`、`tmp*` 前缀、`check*.py` 加入可再生表 | 4241 条影子审计里的 3 条真误报 |
| **E** ⭐ | 09-29 | 修**结构性**漏放：原来只取第一个命中的高危模式，`return` 掉了后面更高分的匹配 | 同一个缺陷在本项目里出现过三次；改为逐模式打分 + 按命中区间去重 |
| **F** | 09-29 | `fs.rm(` / `rmdir(` / `unlink(` / `rimraf` 进 HIGH | 内联脚本的删除调用**一条都没覆盖** |
| **G** | 09-29 | `git push` 放宽为允许中间参数 | 原来要求 `git` 与 `push` 紧邻，`git -c url.insteadOf="" push --force-with-lease` 直接漏掉，实测判成 0.05 |
| **H** ⭐ | 09-29 | `-Verb RunAs` / `runas` 进 HIGH（0.90）；`-ArgumentList` 进 `_EXECUTES_CODE`；0.15「危险词仅出现在引号内」分支改为**条件** return | 修之前：`Start-Process powershell -ArgumentList "Remove-Item -Recurse -Force D:/data" -Verb RunAs` 判 **0.15 直接放行** —— 无害的命令在弹窗，危险的命令在静默 |
| **降档** | 09-29 | `Start-Process` 0.50 → **0.25** | 三条理由：① 起进程不丢数据，其对偶动作 `Stop-Process`（可能丢未保存工作）才 0.30 —— 启动不该比杀进程严；② 危险在载荷不在动词，载荷已照扫；③ 提权单独站住 0.90，不跟着降 |

### 回归数据

在 4241 条真实调用上回放，累计补丁 A–H：

- 打扰率 **4.39% → 4.08%**（67 处变化：25 处升档、42 处降档）
- E/F/G 单独：20 处升档、**0 处降档**（补真漏放，不误伤）
- H + 降档单独：**0 处升档**、5 处降档（逐条核对过全文，均为预期）

## 已知边界

诚实列出，免得被当成比实际更强的东西：

- **不防提示注入。** 门控看的是「这条命令危不危险」，不是「AI 是不是被骗了才执行它」。
- **正则会漏。** 补丁 F/G 就是被真实回放打脸之后补的。任何模式匹配系统都需要持续回放审计。
- **`cordis_run` 一律问。** 它激活的是插件代码，没有可判的命令文本，所以 fail-closed 全问。
- **挂不上就是全挂。** hook 进程起不来时，DSH 侧不会报错、只是静默不弹窗。
  所以 `preflight.py` 会检查解释器路径、入口文件、日志可写性 —— 用 `install.py` 生成的
  配置走系统 python，避开「升级后带版本号路径变了」这个坑。
- **只在 DSH 上实测过。** 适配层是 `PreToolUse` 的 stdin/stdout JSON 协议，
  理论上能接到任何走同一协议的宿主，但没有实测。
